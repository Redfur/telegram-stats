## [0.3.0] - 2026-09-23

### Добавлено
- Блок «Таймлайн участников» на дашборде: сколько человек прошло через
  чат, кто сейчас в группе, история входов/выходов/удалений по каждому
  участнику, состав чата во времени и групповые события (создание чата,
  смена названия/фото, миграция в супергруппу). Требует переимпорта для
  чатов, загруженных до этой версии.
- Лог-файл приложения (стандартная директория логов ОС, дублируется в
  консоль при `pnpm tauri dev`) с таймингами этапов импорта — чтобы
  можно было увидеть, на каком именно шаге завис конкретный импорт.
  Расширено на все команды бэкенда: любая ошибка (не только импорт)
  теперь попадает в лог с именем команды, действия, меняющие данные
  (удаление чата, слияние/скрытие/переименование участников) — с
  затронутыми id, а необработанные паники — тоже в лог, а не молча
  теряются в собранном .exe без консоли.
- Шапка страницы дашборда: тип чата, период и название, и, если чат хоть
  раз переименовывался, полоса истории названий под ним — ширина
  сегмента пропорциональна сроку действия названия, тултип на наведении
  показывает имя, период, срок и кто переименовал (для самого раннего
  сегмента без восстановимого названия — честное пояснение, что сама
  выгрузка не содержит истории до этого момента, а не молчаливая
  заглушка). Не показывается для чата, который ни разу не
  переименовывали, и для чата, загруженного до миграции таймлайна
  (требует переимпорта).

### Изменено
- Название приложения: везде заменено «archive» на «stats», ярлык
  Windows после установки — «TG Stats».
- Скроллбар стилизован под тёмную тему вместо системного.
- Тип чата (в шапке дашборда и в карточке библиотеки) — человекочитаемый
  текст («группа», «личная переписка», «канал»...) вместо сырого
  значения формата экспорта («private_group» и т.п.).

### Исправлено
- Убрана белая вспышка фона при запуске приложения.
- Переимпорт чата с большим числом участников больше не подвисает без
  ошибки на этапе финализации (отсутствовали индексы, из-за которых
  слияние участников при переимпорте гоняло полный скан сообщений всей
  базы на каждого участника). Затрагивало все чаты, не только новые.
- Кнопка «Отменить» во время импорта была задизейблена на этапе
  финализации (реконсиляция участников, пересчёт метрик реимпорта) — а
  сам бэкенд после чтения файла отмену вообще не проверял. Теперь
  кнопка активна всё время, а отмена реально прерывает и сверку
  участников, и пересчёт метрик, не оставляя частично сохранённых
  данных.
- Реимпорт чата с полноценной историей реакций (сотни тысяч сообщений)
  подвисал на десятки секунд без ошибки на удалении старых сообщений —
  у таблиц реакций не было индекса, ведущего `message_id`, только
  составные с `chat_id` первым, из-за чего каждое удаляемое сообщение
  гоняло полный скан этих таблиц. Тот же баг бил и по обычному удалению
  чата из Библиотеки для чата с реакциями.
- В «Участниках» больше не появляется сам чат как участник с 0
  сообщений — Telegram помечает анонимные действия админа в
  супергруппе (смена названия/фото и т.п.) actor'ом, чей id совпадает с
  id самой супергруппы; такой actor больше не заводит фиктивную строку
  участника. Чинится самостоятельно при первом открытии дашборда или
  участников для уже импортированных чатов, без переимпорта.

# План разработки

Верхнеуровневый план по фазам, в порядке зависимостей. Каждая фаза — один или
несколько вертикальных срезов; перед стартом каждого показывается план и
ждётся подтверждение (см. CLAUDE.md «Как я хочу работать»). Порядок фаз 0–3
жёсткий: без импорта и людей метрикам считать не над чем. Порядок 4–7 внутри
себя подвижный и совпадает с `docs/SPEC.md` §9 («базовые → медиа →
социальные → языковые»).

Статус: 🔲 не начато · 🔶 в работе · ✅ готово

**MVP-срез (сентябрь 2026).** По просьбе пользователя увидеть рабочий MVP
раньше, чем дойдёт очередь по фазам, сделан один сквозной вертикальный
срез поперёк Фаз 1/2/4: минимальная SQLite-схема, Tauri-команда импорта,
выбор файла через нативный диалог, чат появляется в рельсе и открывается
в дашборде с тремя метриками (сводка, активность с авто-гранулярностью,
топ участников). Ниже это разнесено по своим фазам с пометкой, что именно
сделано в MVP-объёме, а что осталось для полной версии фазы.

## Фаза 1 — Импорт
1. ✅ Фикстуры `tests/fixtures/`: трёхдневный чат, переписка на двоих,
   группа на 50 (с deleted account, ботом, сервисными событиями, poll,
   location_information), чат без реакций, англоязычный чат. Форма — по
   разведке реального экспорта пользователя (только структура полей,
   никакого реального контента)
2. ✅ Стриминговый парсер `src-tauri/src/import/`: `parse_export()` читает
   `result.json` через `serde_json::Deserializer::from_reader` и кастомный
   `Visitor`/`DeserializeSeed` по полю `messages`, вызывает колбэк на
   каждое событие, не собирая `Vec` внутри себя. `text`/`text_entities`,
   `from_id`-идентичность, отсутствующие/числа-или-строки поля — по
   SPEC §8. Несмоделированные поля (poll, rich_message,
   inline_bot_buttons, contact_information, todo_list, game_*) уходят в
   `extra` через `#[serde(flatten)]`, не роняя парсер. 13 тестов
   (`cargo test`), `cargo clippy` чист. SQLite/Tauri-команда/UI — ещё нет,
   `parse_export()` пока ничем не вызывается кроме тестов
3. ✅ SQLite: миграции `0001`–`0003` (`src-tauri/src/db/migrations/`) —
   `chats`/`people`/`messages` + `aliases` + `people.merged_into`/
   `is_hidden` (Фаза 3). Ещё нет `reactions`/`links`/`tokens` и строк для
   сервисных событий (ни одна текущая метрика их не читает; понадобятся —
   ещё одна миграция, реимпорт это уже поддерживает). Одна транзакция на
   импорт, `person_id` резолвится через `HashMap` в памяти, WAL,
   `chats.id` переживает повторный импорт того же `tg_chat_id` — и теперь
   `people.id`/`merged_into`/`is_hidden`/алиасы тоже переживают (см. п.
   Фазы 3 ниже: реконсиляция сопоставляет по `tg_person_id`, а не стирает
   и перезаливает). `CountingReader` считает прогресс по байтам файла
   (без второго прохода ради подсчёта сообщений), throttled-эмит
   `ingest://progress` раз в ~150 мс, отмена — `AtomicBool`-флаг,
   проверяется раз на сообщение, некоммит транзакции чистит всё сам.
   Батчи по 5000 отдельными транзакциями — по-прежнему не сделаны (одна
   транзакция на весь импорт справляется с целевыми объёмами; понадобятся
   отдельные батчи — если реальный профиль на многомиллионном чате
   покажет проблему)
4. ✅ Импорт: нативный диалог выбора файла (`@tauri-apps/plugin-dialog`),
   `ImportFlowOverlay` (`src/components/ImportFlow/`) — прогресс-карточка
   с процентом по байтам и кнопкой «Отменить», карточка ошибки с текстом
   по `kind` (`not_telegram_export`/`invalid_json`/`message_error`/`io`,
   классификация на границе Tauri-команды, макет 3c — адаптирован под то,
   что реально проверяет парсер, не дословно скопирован). Отдельного
   постоянного экрана Импорта (роут в наве) — по-прежнему нет, оверлей
   триггерится из Библиотеки, это и есть макетный шаг 1 без лишнего роута

## Фаза 2 — Библиотека чатов
✅ Полноценный экран (`src/screens/Library/Library.tsx`) по макету 3a:
сетка карточек (`LibraryCard`) — тег типа, период, сообщения/участники,
три действия (Открыть / Обновить выгрузкой — тот же `import_chat`,
идентификация по `tg_chat_id` уже это поддерживает / Удалить — новая
команда `delete_chat`, каскад по `chat_id` через `ON DELETE CASCADE`,
подтверждение через `ConfirmDialog` на `@radix-ui/react-alert-dialog`).
Шапка — агрегат по всем импортам, включая честный объём на диске
(`chats.source_file_size`, миграция `0002`, считается один раз в
Tauri-команде из `fs::metadata` при импорте). `LibraryEmptyState` (макет
3b) остаётся как есть для пустой библиотеки.
Не сделано (следующие срезы): карточка «чат ещё импортируется» прямо в
сетке (макет 3a) — `ingest://progress` уже есть (Фаза 1 п.3), но прогресс
сейчас показывается полноэкранным оверлеем (`ImportFlowOverlay`), а не
инлайн в карточке, и параллельные импорты по-прежнему не поддержаны;
строка «доступно N метрик из M» — нет системы объявления требований
метрик (Фаза 4); явный выбор при конфликте `tg_chat_id` для старых
экспортов без `id`; список вместо сетки, drag-and-drop.

## Фаза 3 — Участники
🔶 Таблица участников с историческими именами (`aliases`, копится во
время импорта — буфер по уникальным парам человек/имя, не по
сообщениям), переименование, скрытие, объединение дублей
(`merge_people` — мягкое удаление через `merged_into`, сообщения
переезжают на «главного») и поиск по имени — общее ядро
`ParticipantsManager` (`src/components/ParticipantsManager/`), макет
3d/3e. Используется в двух местах: шаг 3 мастера импорта
(`ParticipantReviewStep` — модальный chrome, открывается после каждого
успешного импорта) и самостоятельный экран «Участники»
(`src/screens/Participants/`) — теперь реальный пункт нава, открывается
для уже выбранного в рельсе чата (макет 3d: чат в рельсе и пункт нава
подсвечены одновременно; повторный клик по чату в рельсе возвращает на
дашборд). Метрики (`get_top_participants`, `get_chat_totals`,
`list_chats`) фильтруют `merged_into IS NULL AND is_hidden = 0` и
считают `participant_count` вживую, а не из снимка на момент импорта.
Не сделано: авто-детект похожих дублей/ботов, сегмент-фильтр
«Все/Дубли/Боты/Скрытые» и сворачивание хвоста для больших чатов (макет
3e) — для них нет честного сигнала в текущих данных (нужен отдельный
эвристический шаг детекции, которого нет).

## Фаза 4 — Дашборд, базовые метрики
🔶 Сделаны три метрики из «Базовых» — секции 00/01/02 макета «Дашборд»
(вариант 2a): сводка (сообщений/слов/в день/участников), активность с
автогранулярностью (`src-tauri/src/metrics/granularity.rs` — чистая
функция, переиспользуется любой будущей time-series метрикой; UTC,
часовой пояс экспортёра не восстанавливается и честно помечен в UI), топ
участников с вырождением в соотношение для чата на двоих (§7). Средняя
длина сообщения — тем же запросом, не отдельная метрика.

Плюс секция 03 — универсальный блок «Типы сообщений» (ход `t6` макета
«Дашборд», см. `docs/SPEC.md` §9 «Типы сообщений»): переключатель на 12
типов (медиа: фото/стикер/голосовое/кружочек/видео/гифка/файл; флаги:
пересланное/отредактированное/опрос/геометка/контакт) с бейджем-счётчиком,
карточка сводки (две раскладки — частота с пиком/лидером для десяти
типов, длительность суммарно/медиана/максимум для голосовых/кружочков),
гистограмма по выбираемой гранулярности (месяц/день/час суток —
свой, трёхуровневый выбор, не переиспользует `Granularity`) и таблица
участников. Миграция `0004` добавила `messages.media_type`/`has_photo`/
`has_file`/`has_poll`/`has_location`/`has_contact`/`forwarded_from`/
`edited_ts`/`duration_seconds` и `chats.message_types_ready` (чаты,
импортированные до этой фичи, показывают «Обновить выгрузку» вместо
лживых нулей — тот же паттерн деградации, что и у отсутствующих
`reactions` в старых экспортах). Реакции как 13-й тип — сознательно не в
этом срезе: нужна отдельная таблица `reactions` и это уже метрика
Фазы 6, а не универсального блока (см. `docs/SPEC.md` §9). Мультивыбор
типов для сравнения на одном графике и слайд «Типы сообщений» в наборе
Фазы 8 — заявлены в самом макете как следующий шаг, не в этом срезе.
`UnavailableCard` (`src/components/ui/`) — общий примитив для паттерна
«метрика недоступна», заведён этим срезом, переиспользуется будущими
метриками с опциональными требованиями к данным (§7).

Не сделаны: тепловая карта день×час (нужен отдельный 2D-компонент),
рекордный интервал/самая долгая тишина, период/фильтр участника/
переключатель чата с самого дашборда (секция 04 макета и полная версия
экрана из SPEC §10).
